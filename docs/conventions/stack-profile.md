# Stack profile — crumble-logbook

Every `rubber-duk-*` agent reads this file before it reviews or writes code. It holds what depends on
this stack: the versions to look up rather than remember, the skills to load, and the hunt lists.
`AGENTS.md` wins wherever they disagree. The package layout is README § What's here.

## The stack

- pnpm 12.6 workspace (`pnpm-workspace.yaml`), Node 24.18+, ESM, TypeScript everywhere but the macro.
  `tsconfig.base.json` is strict with `noUncheckedIndexedAccess` and `verbatimModuleSyntax`.
- `tsc` is TypeScript 7 (native). ESLint runs on the TypeScript 6 that `tools/eslint-config` carries,
  because typescript-eslint needs the JS compiler API.
- `apps/server`: Hono 4 over SQLite, through Node's `node:sqlite` and drizzle-orm 1.0 beta
  (`drizzle-orm/node-sqlite`), run with `tsx`. Layers are `routes → services → repos → db`, held by
  `test/architecture.test.ts`. Content types are declared once in `src/registry.ts`. `src/importers/`
  loads research records; `src/cli/` holds the import, snapshot and Vercel build commands;
  `src/vercel.ts` is the read-only deployment.
- `apps/web`: React 19, TanStack Router file routes (`src/routes/`, generated `src/routeTree.gen.ts`),
  TanStack Query, Hono's typed client `hc<AppType>` (`src/api/client.ts`), Vite 8. Charts are
  hand-written SVG components; there is no chart library. Styles are plain CSS in `src/styles/`, read
  through the tokens in `tokens.css`, light and dark.
- `packages/schema`: Drizzle tables (`src/tables/`), drizzle-kit migrations (`migrations/`), and the
  Zod schemas the server and the web share.
- `packages/capture`: the scrapers and the capture ledger, pure I/O, run as `pnpm capture`.
- `tools/conquest-hud`: run by Node directly (`node src/cli.ts`), so its imports end in `.ts` and its
  syntax must be erasable (`allowImportingTsExtensions`, `erasableSyntaxOnly`).
- `tools/conquest-macro`: AutoHotkey v2. No TypeScript gate reaches it; its README covers checking it.
- One gate: `pnpm verify` (typecheck → eslint → prettier check → vitest).

## Framework docs and skills

- None of the frameworks ships its docs in `node_modules`. The installed `.d.ts` files are the ground truth for
  a signature; next comes the official documentation for the installed major (versions in each
  `package.json`). Look these up before trusting training data:
  - drizzle-orm 1.0 beta: the `drizzle-orm/node-sqlite` driver and migrator, and `drizzle-orm/zod` in
    place of `drizzle-zod`. Examples built on `better-sqlite3` or `drizzle-zod` don't apply.
  - Zod 4, whose error and schema APIs differ from Zod 3.
  - Vitest 4 and Vite 8, whose config and plugin APIs move between majors.
  - TanStack Router's file routes, generated by `@tanstack/router-plugin`.
  - `node:sqlite`'s `DatabaseSync`: synchronous, so repos and `store.transaction` are synchronous too;
    an async callback is a type error.
- Skills to load before touching a surface:
  - `vitest` for any test work (see the version caveat under Unit tests).
  - `agent-browser` for any check in a browser, run as `AGENTS.md` says (headed, named session).
  - `web-design-guidelines` for a UI review.
  - `dataviz` before changing a chart or the categorical series tokens in `tokens.css`, which were
    validated with it.
  - `deep-research` for anything under `research/`: a record follows its contract.

## Review hunt list (rubber-duk-review, rubber-duk-backend)

Server:

- A route importing `repos/`, `db/` or `drizzle-orm` → call a service. The architecture test fails it.
- A service building drizzle queries or importing `hono` → the query goes in a repo; the service
  throws `NotFoundError`, `UnknownRefsError` or `ConflictError` from `src/errors.ts`, and `createApp`
  maps them to 404, 422 and 409.
- A hand-rolled 400, or `zValidator` called directly → `validate()` from `src/routes/validate.ts`, which
  answers every Zod issue with its path.
- A type added to `registry.ts` without its own `.route()` line in `src/app.ts`, or routes mounted in a
  loop → spell the `.route()` out, or `AppType` loses that route's types; `test/registry.test.ts`
  checks every registered path is mounted.
- Writes across tables outside `store.transaction` → run them inside it, with the repos it binds.
- A derived figure stored, or taken from the request (`ratio`/배, `powerG`, a dungeon run's
  `standing`) → compute it on read or on every write; the server ignores the posted copy.
- Ranking by 배 → rank by damage (or stage reached, then lowest power). 배 only normalises.
- A `console` call outside `src/cli/`, `src/main.ts` and `src/app.ts` → let the error propagate;
  ESLint's `no-console` fails it.
- An importer reaching services, routes or `hono` → only what `importerMayImport` in the architecture
  test allows.
- A table change without a generated migration → change `packages/schema/src/tables/`, then
  `pnpm --filter @crumble/schema db:generate`.
- A recommendation deleted from a curated file → mark it `obsolete` (README § The database).

Web:

- A component importing `src/api` → components take props; routes and views fetch.
- `src/lib/` importing `api`, `app`, `views` or `routes` → keep `lib/` pure.
- A value import from `@crumble/server` → type-only; requests go through `hc<AppType>`.
- A filter change that pushes a history entry → `useSearchPatch` (`src/app/search.ts`), which replaces it.
- A colour, size or spacing literal in a component or sheet → a token from `tokens.css`, defined for
  both themes.
- A chart library → an SVG component beside `Scatter.tsx` and `AttemptCharts.tsx`.
- A per-mode route file → a mode is a file in `src/app/modes/`, served by the shared routes under
  `src/routes/$mode/`.

Everywhere:

- A function, method, class or interface method without full JSDoc → `comment-policy.md`; ESLint fails it.
- A switched-off lint rule without its reason → each one in `tools/eslint-config/index.ts` carries an
  inline comment saying why.

## Security surface (rubber-duk-auditor)

No auth, no cookies, no CORS and no CSP: the API serves the local web app through Vite's proxy, and the
only hosting is a read-only Vercel deployment of the committed snapshot.

- **Canonical config:** `apps/server/src/vercel.ts` (anything but `GET` and `HEAD` answers 405 with
  `Allow`), `apps/server/src/cli/build-vercel.ts` (what the function bundles), `vercel.json` and
  `.vercelignore`. The app sets no response headers of its own. Read these end to end before a
  deployment finding.
- **Public by design:** the whole repo, text and JSON captures included, and `data/snapshot.json`,
  which carries the account rows when `import:account` ran before the export.
- **Never committed:** what `.gitignore` excludes stays local; the media extensions under `research/`
  are `MEDIA_EXTENSIONS` in `packages/capture/src/ledger.ts`, kept in step with it. Raw APK or
  decompiled artefacts never enter the repo, ignored or not. The account importer drops screenshot
  fields and image paths; a change that lets one through publishes it in the snapshot.
- **Client/server boundary:** the web imports `@crumble/server` types only (architecture test). It reads
  no `import.meta.env`; `CRUMBLE_API` only points Vite's dev proxy.
- **Local files read per request:** `/api/attempts` reads `tools/conquest-macro/` or the folder
  `CRUMBLE_MACRO` names; the deployment has neither and answers `available: false`.

## Frontend (rubber-duk-frontend)

- The UI rules are `AGENTS.md` § UI: scannable, not prose. The components that carry them:
  - verdicts, tiers and confidence as a `Pill`, whose kind maps to a tone (colour and glyph);
  - anything longer than a line through `Clamp`;
  - sources through `SourceChips`, at the end of a row;
  - a cookie through `CookieName` and `CookieIcon`, which fall back to an initials badge tinted by
    element.
- Colours, type sizes and spacing come from `src/styles/tokens.css`. A new token is defined in the
  light block and in both dark blocks (`prefers-color-scheme` and `[data-theme="dark"]`).
- A new route file needs `src/routeTree.gen.ts` regenerated before typecheck passes (`docs/gotchas.md`).
- Before a UI change is done, every screen it touches is checked in agent-browser, in both themes and
  at phone width.

## Unit tests (rubber-duk-tests)

- Runner: Vitest 4. The root `vitest.config.ts` lists the projects. Each takes its package's name
  (`@crumble/server`, not `server`), so `--project server` silently matches nothing. Scope a run by
  path: `pnpm exec vitest run apps/web/test/attempts-view.test.tsx`.
- Load the `vitest` skill for `test.extend`, `test.for`, `vi.mocked` / `vi.hoisted`, mocking and reset
  semantics. **Version caveat:** the skill may target an older major than the installed Vitest 4;
  verify mocking, fixture and config claims against the Vitest 4 docs.
- Environment: `node`, except `apps/web`, whose `vitest.config.ts` sets `jsdom` and `test/setup.ts`
  (jest-dom matchers, `cleanup` and `vi.unstubAllGlobals()` after each test, a `scrollTo` stub, and a
  style that shows the navigation popover).
- No globals: import `describe`, `it` and `expect` from `vitest`. No `restoreMocks` or `clearMocks`
  either, so a test restores its own spies.
- UI tests use `@testing-library/react` with `fireEvent`; `@testing-library/user-event` isn't installed.
