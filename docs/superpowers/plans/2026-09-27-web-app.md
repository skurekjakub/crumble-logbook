# Web App Implementation Plan (plan 3 of 3)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (batched: one implementer per batch, one Opus review per batch). Steps use checkbox (`- [ ]`) syntax.

**Goal:** `apps/web`, a React app that renders every view the legacy dashboard has, from the API, plus a Piñata boss screen that turns the fight research and the formula findings into one page. Then `legacy/` is deleted.

**Architecture:** Vite + React 19 + TypeScript strict. TanStack Query holds server state; TanStack Router provides typed routes and typed search params for filters. All API access goes through Hono's typed client `hc<AppType>` (a type-only import of `@crumble/server`). The legacy CSS (`tokens.css`, `base.css`, `components.css`) carries over unchanged, so the look is the same. Components are data-agnostic and take props; views compose them.

**Tech Stack:** react 19.3, react-dom, vite 8, @vitejs/plugin-react, @tanstack/react-query 5, @tanstack/react-router 1 + @tanstack/router-plugin (file routes), hono/client, Vitest + @testing-library/react + jsdom.

**Spec:** `docs/superpowers/specs/2026-09-27-crumble-logbook-design.md` (Web section). Builds on plan 1 (`docs/superpowers/plans/2026-09-27-data-core.md`).

## Global Constraints

- Rank by damage, never by 배. The scores table sorts by damage; 배 shows only as a column and as the scatter's reference lines.
- Names are stored in Korean; views show the English name with the Korean beneath it, and fall back to Korean when `en` is null.
- Every claim on screen shows its source chips, which link to the source URL.
- The web never imports server runtime code: only `import type { AppType } from "@crumble/server"`.
- Light and dark themes both work (the legacy tokens), and the layout works at phone width.
- JSDoc on every exported component and function. Inline comments only at gotchas.
- Commits: Read then Write `.git/crumble-commit-msg.txt`, `git commit -F`, explicit `git add` paths, no `git stash`.
- Every reviewer runs on Opus.

## Review Focus

1. **Empty and missing data.** A view with zero rows shows the legacy "empty" message, not a blank or a crash. Test: W3.
2. **An API error** shows an error box naming the failed resource. The rest of the app keeps working. Test: W2.
3. **Unresolved names** (`en: null`) show the Korean name, never "null". Test: W2.
4. **Boss-screen claims marked low confidence** (the DR/ATK ramp) are visibly labelled, never presented as fact. Test: W4.
5. **Numbers:** G/T formatting matches the legacy `formatG` (1312 → "1.31T", 867 → "867G", 0.97 → "0.97G"). Test: W2.

#### W4: The Piñata boss screen (`/boss`)

One page for 지나치게 무거워진 피냐타 (Dark, weak to Light), built from the API only:
1. **Header:** name KR/EN, element Dark, weakness Light, fight length 60 s, score = cumulative damage.
2. **Fight timeline:** a horizontal 0–60 s track (with the in-game countdown shown under it) marking every `fight_events` row. Low-confidence rows are hatched and labelled "unverified claim" (RF4). Each row has its sources.
3. **Survival:** the 30 s slam thresholds (front ≈4.5M / back ≈3.5M HP) and the 17 s-remaining wipe (~9M HP + 45% DR), from mechanics and fight events, with sources.
4. **Buffs by star:** a table from `buff_values` (cookie × star → value), with a note that each buff scales with the caster's skill amp.
5. **What to run:** per-cookie rune guidance from `rune_builds` (why + disputed), the Brightseeker haste breakpoint (~45–50 in battle), and Dark Choco focus.
6. **ATK-order check:** the Cherry deck's ATK chain from the deck, plus the in-battle checks (Scorpion below Cheesecake after Octo Wasabi's +8%; all six buffers above the catcher).

Tests: timeline positions scale 0–60; low-confidence events render the unverified label; the buff table pivots grades to stars correctly.
