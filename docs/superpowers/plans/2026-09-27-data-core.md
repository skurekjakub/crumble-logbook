# Data Core Implementation Plan (plan 1 of 3)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The schema package, the Hono data API over SQLite, and the importer that loads research record 001 end to end, so every row the legacy dashboard shows is served from the database with its citations.

**Architecture:** `packages/schema` owns the Drizzle tables, the generated migrations and every Zod schema. `apps/server` is layered: `routes → services → repos → db`. Importers and CLIs talk to repos through a `Store` (repos + transaction). A generic content service and router cover the simple cited tables; decks and rune builds are hand-written aggregates.

**Tech Stack:** Node 24.18 (ARM64 Windows), pnpm 12.6 workspace, TypeScript 7.0.2 strict, `node:sqlite` via `drizzle-orm@1.0.0-beta.22` (`drizzle-orm/node-sqlite`, `drizzle-orm/zod`), `drizzle-kit@1.0.0-beta.22`, zod 4, Hono 4 + `@hono/zod-validator` + `@hono/node-server`, Vitest 4, tsx.

**Spec:** `docs/superpowers/specs/2026-09-27-crumble-logbook-design.md`. Plan 2 (jobs + scrapers) and plan 3 (web + legacy removal) follow and build on the API this plan ships.

## Global Constraints

- Rank by damage, never by 배. 배 (damage ÷ power) is computed on read and never stored.
- Every content row carries ≥1 citation. An unknown source id is a 422 that names the ids.
- Cookie and pet names are stored in Korean as written. The glossary resolves them on read, and an unresolved name comes back as `en: null`.
- Every deck cookie carries a `level` or a `levelRule`, plus a non-empty `why`.
- Validation failure → 400 listing every Zod issue with its path. Unknown id → 404. Conflict → 409.
- The importer is all-or-nothing: one transaction, and errors name the file and the row.
- Evidence under `research/*/evidence/` is never edited. Tests read it; they never write it.
- No network in tests. Tests use `openDb(":memory:")`.
- Layering: routes call services only; services call repos only; only repos import `drizzle-orm` query builders. The web (plan 3) imports only `type AppType`.
- JSDoc on every exported function: what it does, params, returns, how it fails. Inline comments only at gotchas. No narrative comments.
- Files stay focused: one aggregate per repo/service/route module.
- Commits: write the message to `.git/crumble-commit-msg.txt` (Write tool) and run `git commit -F .git/crumble-commit-msg.txt`. Subject line, then a body with the problem, why this approach, and what was discarded. End with `Co-Authored-By: Claude Opus 5.5 (1M context) <noreply@anthropic.com>`. A single `-m` is blocked by a hook.
- Run tests scoped: `pnpm vitest run <path>`. The whole gate is `pnpm verify`. Unscoped `npx vitest run` / `npm test` are blocked by a hook.
- Drizzle 1.0 beta and TS 7 are pinned; don't upgrade them.

## Review Focus

1. **Deleting a source that rows still cite** must be a 409 naming the count, never a raw SQLite FK error or a 500. Test: Task 8.
2. **PATCH without `sources`** must keep the existing citations; PATCH with `sources: []` is a 400. Test: Task 5.
3. **Re-running `import:record` on a populated database** must refuse with a clear message unless `--replace` is given; it must never duplicate rows. Test: Task 11.
4. **Seed values the dashboard tolerated but the schema doesn't**: the `"?"` date on `web:allthingshow-guild-conquest`, `""` element/class/rarity in the glossary, `null` glossary `en`, `null` score `power_g`. Import maps them to `null`, it doesn't fail. Test: Task 10.
5. **A deck PATCH that omits `pets`/`notes`** must leave them alone. Zod defaults must not leak into patch schemas and wipe children. Test: Task 3 (schema) and Task 6 (service).

`src/zod.ts` — pattern (proven in the spike: the callback's result replaces the column schema entirely, so nullable columns must re-add `.nullish()` themselves):

```ts
import { createInsertSchema, createSelectSchema } from "drizzle-orm/zod";
import { z } from "zod";
import * as t from "./tables";

/** ISO calendar date, `YYYY-MM-DD`. */
export const isoDate = z.string().regex(/^\d{4}-\d{2}-\d{2}$/, "expected YYYY-MM-DD");
/** A citable source id: `<site>:<key>`. */
export const sourceId = z.string().regex(/^(dc|nv|web):.+$/, "expected <site>:<key>");
/** A deck id: lowercase slug. */
export const deckSlug = z.string().regex(/^[a-z0-9]+(-[a-z0-9]+)*$/, "expected a lowercase slug");
const nameList = z.array(z.string().min(1));

export const sourceInsert = createInsertSchema(t.sources, {
  id: () => sourceId,
  url: (s) => s.min(1),
  date: () => isoDate.nullish(),
  relevance: (s) => s.int().min(0).max(3).nullish(),
});
export const sourceSelect = createSelectSchema(t.sources);
// …same for every table. Overrides to apply:
// glossary: shorthand nameList.optional() (insert) / nameList (select); extra z.record(z.string(), z.unknown()) (.optional() on insert); kr min(1)
// decks: id deckSlug; atkOrder nameList.nullish() / nameList.nullable(); nameEn min(1)
// deckCookies: why (s) => s.min(1); cookieKr min(1)
// scores: damageG (s) => s.positive(); powerG (s) => s.positive().nullish(); date isoDate.nullish(); season int positive nullish
// rankings: capturedAt min(1)
// timeline: date () => isoDate
// recommendations: changes nameList.min(1)
// jobs: params z.unknown(); log z.array(z.string()) (.optional() on insert)
```

The generic repo (compiled in the spike; keep the casts exactly where they are — they're what makes a generic Drizzle table type-check):

```ts
type IdTable = SQLiteTable & { id: SQLiteColumn };

/**
 * CRUD over a table with an integer `id` primary key.
 * @param db - database or transaction handle
 * @param table - the Drizzle table
 * @param orderBy - list order; defaults to ascending id
 * @returns the repo; `get`/`update` return undefined for an unknown id
 */
export function createTableRepo<T extends IdTable>(db: Db, table: T, orderBy: (SQL | SQLiteColumn)[] = [asc(table.id)]): TableRepo<InferSelectModel<T>, InferInsertModel<T>> {
  type Row = InferSelectModel<T>;
  const base = table as SQLiteTable;
  return {
    list: () => db.select().from(base).orderBy(...orderBy).all() as Row[],
    get: (id) => db.select().from(base).where(eq(table.id, id)).get() as Row | undefined,
    insert: (values) => db.insert(base).values(values as InferInsertModel<SQLiteTable>).returning().get() as Row,
    update: (id, patch) => db.update(base).set(patch as Partial<InferInsertModel<SQLiteTable>>).where(eq(table.id, id)).returning().get() as Row | undefined,
    remove: (id) => db.delete(base).where(eq(table.id, id)).returning({ id: table.id }).all().length > 0,
    count: () => db.$count(base),
    clear: () => { db.delete(base).run(); },
  };
}
```

(If `db.$count` isn't on `BaseSQLiteDatabase` in this beta, use `db.select({ n: count() }).from(base).get()!.n`.)

## Decisions this plan makes beyond the spec (for review)

- **drizzle-orm 1.0 beta**, pinned: the only Drizzle release with a `node:sqlite` driver. drizzle-zod is `drizzle-orm/zod` in 1.0.
- **Migrations live in `packages/schema/migrations`** next to the tables. The server imports the folder path through the node-only subpath `@crumble/schema/migrations`, so the web never pulls in `node:sqlite`.
- **`sources.title`** instead of `title_kr`, because web sources' titles are English. It holds the original-language title. Added `note` (for the non-relevance signal such as "public game data") and `summary_en` (from the extractions).
- **`research_records` gains `season_label`, `lede` and `caveat`**, and a new cited **`recommendations`** table holds the dashboard's "for your account" block. The dashboard's footer and gear-slot labels are UI copy and move to the web app (plan 3).
- **`glossary.extra`** (JSON) keeps the fields the spec's columns don't name, so the import loses nothing.
- **`rankings` gains `power_g`, `ref`** (crumb.gg player id) **and a `source_id` column** instead of polymorphic citations. Rankings are bulk captures, one source per board.
- **`import:record` loads into an empty database** (or `--replace`). Record-scoped re-import would need content rows to carry a record slug, which the spec doesn't have. That becomes a problem when record 002 exists.
- **The curated dataset moves into the record** (`research/001-…/curated/`), so the import survives deleting `legacy/` in plan 3. After import the database is the source of truth, and `data/snapshot.json` is its committed, diffable history.
